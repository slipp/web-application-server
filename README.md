### 세션이란?
* 쿠키의 보안 측면의 단점을 해결하기 위해 세션 활용
* 세션은 상태 정보를 클라이언트(브라우저)에 저장하지 않고 서버에 저장함.
* 클라이언트-서버 간 상태 값을 공유하기 위해 고유한 아이디를 발급하고, 이 아이디는 쿠키를 활용하여 공유(Set-Cookie)

### 세션 클래스 구현
* HttpSessions: 모든 세션을 관리하는 저장소 역할, 세션 ID를 통해 HttpSession 객체를 생성하거나 조회
* HttpSession: 개별 사용자의 세션 정보를 저장하고 관리

### 쿠키 값을 설정할 때는 logined=true로 설정했었는데, 세션으로 변경될 때는 왜 User 객체를 전달하는가?
* 쿠키의 목적: 쿠키는 주로 클라이언트의 상태를 유지하기 위해 사용됩니다. logined=true는 사용자가 로그인했음을 간단히 나타내는 플래그로, 클라이언트 측에서 로그인 여부를 확인하는 데 사용됩니다. 그러나 이 정보는 매우 제한적이며, 사용자의 세부 정보를 확인하기에는 부족합니다.
* 세션의 목적: 세션은 서버 측에서 관리되며, 사용자의 상태를 저장할 수 있는 보다 복잡한 구조입니다. 세션은 사용자의 로그인 정보를 포함하여, 사용자 ID, 이름, 이메일, 권한 등 다양한 정보를 포함할 수 있습니다. 이로 인해 서버는 사용자의 세부 정보를 쉽게 관리하고, 여러 요청 간의 상태를 유지할 수 있습니다.
